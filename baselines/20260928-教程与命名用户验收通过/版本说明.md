# 0.2.1 教程与命名用户验收版

本目录保存 2026-09-28 的教程与导出命名验收基线，适配当时的 AzureArchive 1.0 fix4。用户亲自操作后确认「已经没有问题了」，随后要求保存新基线并清理测试数据。插件版本仍为 **0.2.1**，以本目录日期和名称区分开发快照；不要将它解释为后续 V1.0 或 V1.1 安装器版本。

版本号见 [manifest.json](RecorderMod/manifest.json)，功能和验收过程见 [当时的开发记录](RecorderMod/DEVELOPMENT.md)。本说明根据该快照内保存的记录、源码和素材来源整理，未重新运行测试。

DLSS 总开关来自此前单独通过验证的基线：每次打开内录设置默认关闭；未主动开启时，超分、补帧、神经渲染标题与控件置灰，点击不能改变参数，普通录制也不会启动增强任务。显卡受支持且主动开启后，三项增强才可操作。不支持显卡时总开关禁用并显示红色提示，普通录制仍可用。

上述行为与教程共同回归，但总开关本身不是本版首次加入的功能。后续版本的“缺少 DLSS 组件即禁用总开关”、独立补充组件安装器、联网下载向导及安装器中的可选 DLSS 流程，均不属于这份历史快照的验收范围。

## 六步原生风格教程

### 触发、回看与退出

自动教程在当前 MOD profile **第一次进入内录设置时**触发，不是在导入 MOD 或启动 AA 的瞬间弹出。`[Tutorial] SeenVersion` 默认是 `0`；当前教程版本为 `1`，低于当前版本时显示。完成最后一页或点击「跳过」后写入已看版本并保存配置，再次启动不会自动重复。内录设置中的「新手教程」按钮可随时从第一页重新查看。

教程支持点击当前高亮目标或「下一步」前进、「上一步」返回；右上角「跳过」在所有页面始终高亮且可用。源码也支持左右方向键翻页、Escape 跳过。回看教程本身不改变输出位置、帧率、DLSS 总开关和增强参数；这与“重新打开设置时总开关默认关闭”的既有规则分别处理。

### 背景暗化与输入隔离

布局参考提供的 Blue Archive 官方教程截图，并沿用 AA 原生字体和按钮。真实内录设置保留在背景中，整体暗化，当前目标区域保留亮度，配蓝白边框和黄色向下箭头。

这是一层强模态引导：即使某个背景区域视觉上没有被暗化，也不能直接操作原控件。高亮目标上方的独立点击代理只推进教程，不修改设置，也不触发「开始内录」。全屏输入遮罩拦截背景操作，其他 AA UI 输入相机临时禁用；退出时按进入前记录恢复各自启用状态。教程期间 MOD 快捷键不执行，按钮回调也检查教程状态。相关实现位于 [NativeRecorderTutorial.cs](RecorderMod/src/NativeRecorderTutorial.cs)、[NativeRecorderUi.cs](RecorderMod/src/NativeRecorderUi.cs) 和 [Plugin.cs](RecorderMod/src/Plugin.cs)。

### 纹理生命周期修复

最初六动作测试发现：AA 加载剧情时调用资源清理，尚未显示的教程纹理可能被回收；仅保存托管引用不足以阻止 IL2CPP/Unity 的这次清理，导致后续页面缺图。

最终实现为六张运行时 `Texture2D` 设置 `HideFlags.DontUnloadUnusedAsset`，并保存在 `tutorialArt[]` 缓存中。切页只替换画像控件的 `mainTexture`，不重复解码 PNG；解码失败时销毁该次未完成的纹理并记录警告。六图由 [build.ps1](RecorderMod/build.ps1) 嵌入 DLL，教程运行无需联网。此修复针对剧情资源清理期间的素材保留，不应将其扩大描述为对所有 Unity 资源生命周期的通用改造。

## 日期序号导出命名

普通视频采用本地日期 `yyyyMMdd-N.mp4`，例如 `20000101-1.mp4`、`20000101-2.mp4`；新的一天从 `1` 开始。日期使用本地时间，不是 UTC。

序号属于当前 MOD profile，落盘位置为该 profile **配置目录下**的 `azurearchive.recorder-state/export-sequence.json`。因此，同一 profile 在更换输出文件夹、重启 AA 或多个 AA 实例共用状态目录时继续累计；不同 profile 各有状态，不能理解为整台电脑所有 profile 共用一个全局计数器。

| 类型 | 所选输出目录中的路径 | 序号关系 |
| --- | --- | --- |
| 普通内录 | `yyyyMMdd-N.mp4` | 一次发布分配一个序号。 |
| DLSS 原片 | `原始视频/yyyyMMdd-N.mp4` | 与本次增强成片共用同一个序号。 |
| DLSS 增强成片 | `yyyyMMdd-N.mp4` | 增强完成后发布；取消或失败时保留已经保存的原片。 |

实现集中在 [DailyExportNaming.cs](RecorderMod/src/DailyExportNaming.cs)：

- `Begin` 在分配序号前确认源视频存在；通过 `export-sequence.lock` 的独占文件锁串行分配，同一状态目录的并发调用不会领取重复序号。锁冲突时每隔 40 毫秒重试，最多等待约 10 秒。
- 同时检查最终路径与原片路径的文件、目录占用，跳过已有名称。视频先复制到带唯一标识的 `.partial` 文件，再以禁止覆盖的移动操作发布；序号状态经独立 `.tmp` 文件保存。
- `FinishEnhancement` 将增强结果发布到事先对应的最终路径。若等待增强期间该路径被其他文件占用，发布失败并保留已有文件，不覆盖已有视频。
- 正常返回或受控异常会清理本次临时文件。没有源视频时不消耗序号。内部诊断任务目录与对外视频名称分开保留。

这里的保护重点是并发分号与不覆盖既有文件；不能据此声称断电、强制终止或所有磁盘故障下都能完成整组文件的原子提交。配置中的序号状态损坏时也不能靠删除他人视频来恢复。

此前本机也已完成普通内录、2 倍超分、2 倍补帧、神经渲染和 2 倍超分加 2 倍补帧的实际推理验证，并验证增强取消、超时及进程回收相关修复。这些是继承的功能证据；未覆盖长任务、3/4 倍补帧或其他物理显卡。不支持显卡分支是在 RTX 5080 上显式模拟支持状态为 false，不能表述为 RTX 20 系、核显或其他型号的实机成功。依赖检查通过也不等于实际 GPU 推理通过。

当时最终调试 DLL 的历史 SHA-256 为 `855425D9AAF87ACF0CD3F5E76903DB19DEBB76268912EE8095AF8175591339E7`；原保存快照有 165 个文件复核一致。这两个值用于识别当时验收对象，不代表本次 GitHub 源码整理的文件总数，也不代表此目录附带可执行安装包。
