## 已验证行为

- 精确提示为“DLSS组件缺失，请安装超分MOD包后或继续执行内录安装。”，按钮为“安装”和“取消安装”；默认焦点、Enter 和 Escape 的默认目标均为取消。
- 未加壳和保护版 EXE 均实测 quiet 入口、普通安装主界面入口，以及直接关闭 DLSS 提示。点击取消或关闭后退出码为 2，完整文件哈希及目录集合不变。
- 新 DLSS 回调拒绝时尚未读取 ZIP、搜索 FFmpeg 或创建安装目录；DLSS 与必需依赖分别提示且不重复。旧 API 未传新回调时仍在原回调中收到所有缺项。
- 点击“安装”后确实完成普通内录安装；不会隐式安装 DLSS 补充产品。缺少必需框架和内置 FFmpeg 的原确认仍正常；重复安装取消仍保持完整目录不变。
- 实际 EXE 完成未加壳 → 保护版 → 未加壳双向覆盖。另有 API 版本切换测试核对每个清单文件的内容哈希及一致的文件集合。
- 独立 DLSS EXE 安装 27 个白名单文件、独立 receipt 和卸载 EXE；RTX 30/40/50 的运行库均匹配固定 SHA-256。完整补充目录不再触发 DLSS 缺失，空共同组件 DLL 会触发缺失。
- 补充包真实重复安装的取消保留全部目录及文件；篡改其卸载清单指向内录文件被拒绝，且不修改 profile。
- 内录卸载后，补充包全部文件与目录不变。补充卸载后，保护内录全部文件、配置和用户资料不变。补充卸载保留用户修改过的说明及未知文件。
- 未加壳内录、保护内录、补充包三种随包卸载 EXE 均实际执行，等待其辅助进程后确认删除自有 receipt 和卸载 EXE。其他 MOD、源码、剧情与视频哨兵文件保留。
- 坏 ZIP、实际文件哈希不符、越界清单、ADS、其他 MOD 路径以及真实目录 junction 均被拒绝。写入失败以及清单合法但不可运行的内置编码器均回滚，文件哈希与目录集合恢复。
- 私有 FFmpeg 实际编码及解码 H.264/AAC MP4，验证尺寸、帧率、时长；自定义中文带空格路径和 PATH 中的真实编码器被保留。此次未提供历史 R3 ZIP，旧 R3 升级分支未重跑，因此 FFmpeg 套件计 11 组。
- 两版 MOD 内六个 `recorder.tutorial.arona.page-01.png` 至 `page-06.png` 均存在、内容互异，并与已验收源素材逐一 SHA-256 相同。保护版仅在测试进程内存中解密读取资源元数据，没有执行 MOD 程序集或将解密核心写入磁盘。
- 保护版安装和卸载 EXE 外层均仅有加密负载，AES/GZip 和内存程序集加载结构通过原保护测试。

## 初轮调试与适用边界

- `r6-tests-20260929-212425-907` 是测试程序在窗口尚未显示完毕时就读按钮导致的检测竞态。修正为等待窗口可见并等待按钮后，重新用同一真实安装 EXE 验证通过。
- `r6-tests-20260929-212502-340` 将安装树嵌得过深，遇到 .NET Framework 的 260 字符路径限制。安装器显示错误并停止；与等同初始状态的隔离树比较，31 个文件/目录项完全一致，证据为该目录的 `long-path-rejection-zero-change-proof.json`。正式测试改到较短的独立安装树后通过。本次不宣称支持任意超长 Windows 路径。
- 本套测试证明组件完整性和安装行为，不表示 RTX 30/40 已完成物理显卡推理；也不替代真实 AA 界面的录制、教程或 DLSS 推理验证。

## 重跑入口

使用 PowerShell 7 运行 `packaging/test-r6-installers.ps1`。默认 `-Suite Core` 只运行新的预检测试；`-Suite All` 需提供三个真实安装 EXE 和三个 ZIP 的参数。脚本把源码快照与日志存入新的 `packaging/r6-tests-*`，把安装目标放到新的 `RTX开发测试/R6安装测试/<短ID>`，拒绝复用既有输出目录。脚本不会启动 AA 或执行任何打包、加壳步骤。
