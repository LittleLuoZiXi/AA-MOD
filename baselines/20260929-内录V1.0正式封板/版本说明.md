**AzureArchive 内录 MOD V1.0（1.0.0），2026-09-29 正式封板。** 本快照适用于 Windows x64 的 AA 1.0 fix4，记录从 2026-09-28「教程与命名用户验收通过」基线到 V1.0 的累计开发成果。V1.0 将普通内录和按显卡获取 DLSS 组件的安装流程合并，同时把缺少组件时的增强功能拦截落实到界面与执行入口。该目录保存当时的源码状态，后续修订应保存在新基线中。

本版本的插件、主 manifest 和内录产品身份均为 `AzureArchiveRecorder 1.0.0`，安装器文件版本为 `1.0.0.0`。独立 DLSS 组件产品继续使用 `AzureArchiveDLSSSupplement 1.0.0`；它在 R6 阶段已经是这个版本，不能把旧内录版本 `0.2.1` 当作补充组件的版本。版本入口见 [manifest.json](./RecorderMod/manifest.json)、[插件工程](./RecorderMod/src/AzureArchive.Recorder.csproj) 和 [封板开发记录](./RecorderMod/DEVELOPMENT.md)。

前一基线的详细状态可查阅 [2026-09-28 开发记录](../20260928-教程与命名用户验收通过/RecorderMod/DEVELOPMENT.md)。R6 的过程和验证保留在 [R6 安装测试记录](./RecorderMod/packaging/R6-INSTALLER-TEST-RESULTS.md)；R6 的独立补充包构建代码仍在归档中，用于追溯该阶段，V1.0 正式用户入口则是两份合并安装器。

普通录制继续从 AA 剧情页面「入场」旁的「内录」进入，使用原生设置样式和中文字体。分辨率自动取 AA 所在显示器的物理尺寸，帧率提供 24/25/30/50/60 fps，成品目录可选择并默认使用系统“视频”目录。画面来自离屏相机，声音来自 Unity 内部混音；固定视频时钟、音频同步、按序 GPU 回读和独立进度显示继续保留。录制结束、取消或失败时恢复窗口与相关运行状态。普通 MP4 导出不要求 DLSS 可用，也不会因为显卡不受 DLSS 支持而被禁用。

六页阿罗娜教程沿用前一基线：第一次进入内录设置自动打开，设置内可以回看；背景变暗并拦截背景按钮、功能和快捷键，只有当前目标、上一页、下一页及始终高亮的“跳过”可操作。每页动作和表情不同，翻页切换相应图片，已看状态按 profile 保存。V1.0 更新了 DLSS 页说明，提示通过安装器补齐组件；没有改变六页导航和背景输入屏蔽规则。六张 PNG 作为资源嵌入插件，教程运行不联网。素材是依据官方参考图制作的同人修改素材，来源及光环校正记录见 [教程素材说明](./RecorderMod/assets/tutorial/ASSET-SOURCES.md)。

导出继续使用本地日期与当天序号，例如 `20000101-1.mp4`、`20000101-2.mp4`；跨重启、跨输出目录累计，次日从 1 开始，通过锁与发布检查避免并发覆盖。增强任务的原片放在输出目录的 `原始视频` 子目录，增强片放在所选目录，两者共用同一日期序号；取消增强仍保留原片。教程状态、配置和序号属于用户数据，安装升级与卸载均保留。实现见 [日期命名](./RecorderMod/src/DailyExportNaming.cs) 与 [原生教程](./RecorderMod/src/NativeRecorderTutorial.cs)。

R6 引入的独立组件目录在 V1.0 中继续使用：内录位于 `mods/AzureArchiveRecorder/1.0.0` 及其共用 `runtime`，DLSS 组件位于 `mods/AzureArchiveDLSS/runtime`。内录优先识别完整的独立补充组件位置，同时保留旧工具目录的兼容查找；自动发现不强行改写用户原先保存的 `ToolDirectory`。三个代际库分别使用 `runtime/mods/dlss/rtx30`、`rtx40`、`rtx50`，避免互相覆盖。R6 补充包包含三系，V1.0 的新联网安装只提取本机所需代际与共同文件；已有有效 R6 清单可直接识别和复用。依据见 [组件路径与检查](./RecorderMod/src/DlssComponents.cs)、[部署路径解析](./RecorderMod/src/Deployment.cs) 和 [联网后端说明](./RecorderMod/packaging/ONLINE-DLSS-SOURCES.md)。

V1.0 新增的运行时检查要求同时满足“显卡支持、共同组件存在且非空、本机代际 DLL 摘要匹配”。任何必要条件不满足时，DLSS 总开关和超分、补帧、神经渲染选项都灰色不可操作；支持显卡缺件时显示精确红字：`缺少DLSS组件，相关DLSS功能不可用。` 不支持显卡继续显示其具体原因。设置打开、相关点击、增强录制开始及增强进程启动前都有检查；界面以文件元数据变化触发刷新，录制和增强预检重新计算代际 DLL 的 SHA-256。共同组件的运行时存在性检查与安装器的完整固定摘要校验是两层不同检查。

组件在运行中消失时，本次 DLSS 开启状态会清除；组件恢复后仍需主动开启。旧配置中保存的增强倍率、神经渲染值或 `Enabled = true` 不能隐式启用增强。录制入口移除了缺件时自动下载再继续录制的流程，补充下载统一由安装器负责；普通内录继续可用。详见 [运行时禁用与原生 UI 验证](./RecorderMod/tests/V1-DLSS-RUNTIME-VERIFICATION.md)。

V1.0 安装向导的实际顺序如下：

1. 选择 AA 根目录后列出内录、AA/MOD 加载依赖、FFmpeg 和 DLSS 的已安装或缺失状态。安装器启动时检测显卡，受支持的 DLSS 组件项自动选中，用户不能在该版本的界面上取消自动选择。
2. 先完成普通内录安装，处理依赖、覆盖和 FFmpeg 确认。取消内录确认会终止安装并保持目标零写入；本体安装失败也不会进入 DLSS 阶段。
3. 对受支持的 RTX 30/40/50 系，随后下载共同组件和本机代际附件，校验压缩包和原生文件，完成安全提取及安装事务。已有完整且校验通过的组件则直接复用，不重复下载或改写组件文件。
4. 下载、校验和安装全部完成之前，“继续”保持禁用。暂停、恢复、取消、重试和关闭窗口都有独立状态处理。取消或失败后已经安装的普通内录保留，可重试 DLSS 或退出安装。
5. 完成时更新列表中的内录、FFmpeg、DLSS 状态，显示完整进度与完成文案，隐藏网络提示，再允许继续到结束页。最终封板曾仅重编这一部分显示逻辑，复用了原先已经验证的安装内容与卸载程序。

| V1.0 检测结果 | 安装行为 |
| --- | --- |
| 受支持的 RTX 30/40/50 系 | 自动选择对应 DLSS 阶段；本体成功后才下载或复用组件 |
| RTX 20 系 | **先正常安装内录本体**，随后在 DLSS 阶段提示“暂时不支持20系”并关闭安装向导；保留已安装内录及既有数据，不开始 DLSS 下载。该历史分支退出码为 3 |
| 非 NVIDIA 或未支持型号 | DLSS 控件禁用、红字说明原因；普通内录完成后可正常继续 |
| 不同系列的多张 NVIDIA 显卡 | 拒绝自动选择可能不匹配的代际库，说明原因；仍可安装普通内录 |

以上是 **V1.0 的历史行为**。后续 V1.1 才调整为 DLSS 默认未选、主动勾选后检测以及不支持时取消选择并保留向导；这些规则不属于本快照。另需区分两个开关：V1.0 **安装器**自动选择受支持组件，而 AA 内录设置中的 **运行时 DLSS 总开关**始终需要用户主动开启，每次打开设置默认关闭。对应实现为 [V1 安装向导](./RecorderMod/packaging/V1Installer.cs) 和 [显卡分类](./RecorderMod/packaging/V1Hardware.cs)。

联网后端固定使用 DLSS5Tool v2.3.3 的共同附件和项目收录的 30/40/50 系附件，URL、长度与 SHA-256 写在源码与来源记录中。仅提取实际需要的共同原生文件、语言资源、本机代际库及许可证，不安装完整上游 GUI、历史配置、其他代际或显卡驱动。主安装 EXE 内嵌普通内录安装内容和小型 DLSS 卸载程序，**不内嵌 DLSS 原生组件**。具体附件和固定摘要见 [联网组件来源](./RecorderMod/packaging/ONLINE-DLSS-SOURCES.md)，维护时应同时检查 [C# 代际规则](./RecorderMod/src/GpuProfiles.cs) 与 [Python 代际配置](./RecorderMod/bridge/gpu_profiles.json)。

暂停会中止当前 HTTP 请求并保留本次暂存，恢复通过 Range/If-Range 续传；服务器忽略范围或资源标识变化时从头接收，非法范围与摘要不匹配会拒绝安装。界面每四秒轮换 GitHub 连通性和暂停排查提示。文件先下载到独立临时目录，全部验证通过后才提交目标文件；取消或故障清理本次暂存、回滚本次写入。未知文件或被用户修改的目标文件不会被修复覆盖，旧组件及其余已登记代际保留。该流程由 [OnlineDlssInstall.cs](./RecorderMod/packaging/OnlineDlssInstall.cs) 实现，测试接口仅供同程序集夹具使用，生产入口没有任意下载 URL 或摘要替换开关。

FFmpeg 继续沿用此前规则：先发现并实际验证已有编码器，可用时复用；没有有效版本时明确询问是否安装内置 FFmpeg/ffprobe 7.1.1。取消此确认会终止整个内录安装。内置工具放在 MOD 私有目录作后备，不修改系统 PATH、不覆盖外部 FFmpeg；第三方文件保持原字节和许可。普通 H.264/AAC 导出与 DLSS 可用性独立，安装器的工具探测不能被视为 GPU 增强已成功。实现和历史验证分别见 [安装核心](./RecorderMod/packaging/Installer.cs)、[编码器](./RecorderMod/src/Encoder.cs) 与 [V1 安装验证](./RecorderMod/packaging/V1-INSTALLER-VERIFICATION.md)。

安全升级支持有效的旧 `0.2.1` 内录清单迁移到 `1.0.0`，当前加壳和未加壳版使用相同产品身份与路径，可互相覆盖。活动 profile 设置为当前版本，其他已启用本 MOD 的 profile 一并迁移，其他未启用的 profile 不被强制启用；其他 MOD 条目与自定义字段保留。旧 DLL、manifest 等只有在有效所有权清单内且摘要未变时才清理，修改过或无所有权证明的旧文件保留，profile 不再继续选择旧版本。非法清单、路径穿越、目录链接、重复条目、未知目标冲突和提交失败均有拒绝或事务回滚处理。

两个产品分别拥有安装清单与卸载程序：`mods/AzureArchiveRecorder/卸载内录MOD.exe` 和 `mods/AzureArchiveDLSS/卸载DLSS补充MOD.exe`。卸载只删除清单内且摘要仍匹配的自有文件、清理空目录；配置、教程已看状态、每日序号、剧情、视频、源码、其他 MOD、外部工具和未知或改动文件保留。卸载内录会清理 profile 中的本 MOD 启用项，DLSS 卸载不删除内录。已经完整有效的旧补充包可保留其原有卸载程序；新装组件使用当前安装器提供的对应卸载器。

V1.0 提供两种功能相同的安装器。未加壳版保留可读结构；保护版对 MOD、主安装器及两个卸载器执行混淆、AES/GZip 和内存加载保护，第三方 FFmpeg/NVIDIA 文件不混淆。六张教程图片在两版内录资源中逐项核对，正式内录安装内容每版包含 201 个文件。历史正式 EXE 摘要如下，供与另外保管的安装包核对；本源码归档不包含这些 EXE。
